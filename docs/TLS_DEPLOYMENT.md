# إعداد HTTPS لخادم NEW FEED ERP

يدعم الخادم الآن إنهاء TLS مباشرة باستخدام شهادة X.509 ومفتاحها الخاص، أو العمل خلف Reverse Proxy موثوق يتولى HTTPS. لا يقوم النظام بإنشاء شهادة إنتاجية تلقائياً ولا يتجاوز أخطاء الثقة في تطبيق الموظفين.

## الخيار الأول: HTTPS مباشر داخل Node.js

1. احصل على شهادة صادرة لاسم DNS الذي سيستخدمه الموظفون، مع المفتاح الخاص وسلسلة الشهادات الوسيطة عند الحاجة.
2. انسخ الشهادة والمفتاح إلى مجلد محمي على الخادم، خارج مجلد المستودع.
3. امنح حساب تشغيل خدمة NEW FEED ERP صلاحية قراءة الملفين فقط، وامنع المستخدمين العاديين من قراءة المفتاح الخاص.
4. اضبط ملف البيئة:

```dotenv
HOST=0.0.0.0
PORT=3000
TLS_CERT_FILE=C:/ProgramData/NEW-FEED-ERP/tls/fullchain.pem
TLS_KEY_FILE=C:/ProgramData/NEW-FEED-ERP/tls/private-key.pem
```

5. أعد تشغيل الخدمة، ثم اختبر:

```powershell
Invoke-RestMethod https://erp.example.local:3000/health
Invoke-RestMethod https://erp.example.local:3000/ready
```

استبدل `erp.example.local` باسم DNS الموجود فعلياً في الشهادة. لا تستخدم عنوان IP إلا إذا كانت الشهادة تحتويه في Subject Alternative Name.

## الخيار الثاني: Reverse Proxy

اترك `TLS_CERT_FILE` و`TLS_KEY_FILE` فارغين، واجعل Node.js يستمع على loopback أو شبكة داخلية محمية. أنهِ TLS في Reverse Proxy مثل IIS أو Caddy أو Nginx، ومرّر الطلبات إلى API عبر شبكة موثوقة. لا تعرض منفذ HTTP مباشرة على الإنترنت أو شبكات غير موثوقة.

## ثقة أجهزة الموظفين

- يجب أن تثق Windows في سلسلة الشهادة حتى ينجح اتصال Electron.
- استخدم شهادة من CA موثوقة أو وزّع شهادة CA الداخلية عبر Group Policy بعد اعتمادها من مسؤول البنية التحتية.
- لا تثبّت شهادة جذر مجهولة، ولا تستخدم خيار تعطيل التحقق من TLS.
- تأكد أن اسم السيرفر الذي يُدخله الموظف يطابق اسم DNS الموجود في الشهادة.

## التحقق وحدود القبول

اختبارات CI تتحقق من تحميل إعدادات TLS ورفض الإعداد الناقص والملفات غير القابلة للقراءة. يلزم قبل الإنتاج اختبار الشهادة الفعلية وسلسلتها وتجديدها، صلاحيات المفتاح، اتصال جهاز Windows للموظف، وإغلاق منافذ HTTP غير المطلوبة. هذه الإضافة لا توقّع ملفات EXE ولا تنفّذ تحديثات Windows تلقائية.
