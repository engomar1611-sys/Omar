# تحديثات تطبيق موظفي NEW FEED ERP على Windows

## آلية التحديث
- من قائمة **التحديثات ← التحقق من وجود تحديث** داخل تطبيق الموظفين.
- يعتمد التطبيق قناة GitHub Releases الرسمية للمستودع، ولا يقبل روابط تحديث عشوائية من الخادم.
- التنزيل بموافقة المستخدم، والتثبيت لا يبدأ إلا بعد اكتمال التنزيل.
- التحقق من توقيع كود Windows مفعّل، والرجوع لإصدار أقدم ممنوع.
- عند غياب توقيع صالح أو اختلاف هوية الناشر يفشل التحديث ولا يتجاوز التطبيق التحقق.

## متطلبات النشر الإنتاجي
يجب ضبط أسرار GitHub Actions التالية:
- WINDOWS_CERTIFICATE_BASE64: شهادة Authenticode بصيغة PFX مشفرة Base64.
- WINDOWS_CERTIFICATE_PASSWORD: كلمة مرور الشهادة.
يجب أن تكون الشهادة صادرة للناشر الصحيح. لا تضع ملف الشهادة أو كلمة مرورها داخل المستودع.

## إصدار تحديث
1. حدّث desktop/package.json version إلى رقم جديد.
2. أنشئ GitHub Release بوسم مطابق للإصدار.
3. ابنِ الحزمة باستخدام electron-builder مع CSC_LINK وCSC_KEY_PASSWORD وGH_TOKEN.
4. انشر ملفات NSIS وlatest.yml في GitHub Release.
5. اختبر تثبيت إصدار موقع على Windows ثم تحقق من اكتشاف التحديث وتوقيعه وتثبيته بعد موافقة المستخدم.

## حدود الاختبار
نجاح CI أو إنشاء EXE غير موقع لا يثبت سلامة التحديث الإنتاجي. لا يمكن اختبار التثبيت الآمن قبل توفير شهادة Authenticode وأسرار النشر وإجراء تجربة فعلية على Windows. لا يتم تعطيل التحقق من الشهادة أو التوقيع كحل بديل.
